API Security Testing: The Checklist I Run on Every API

The exact checks I perform before I write a single finding into a report.

1. Authentication

  • Are OAuth 2.0 / OIDC flows implemented correctly? Can the redirect URI be tampered with?
  • JWTs: is the algorithm pinned (alg: none, RS256→HS256 confusion)? Is the secret weak or the key public?
  • Token expiry and rotation — do old tokens stay valid after logout or password change?
  • Brute force: is there rate limiting on login and OTP endpoints?

2. Authorization (the one that actually breaks)

  • BOLA / IDOR: swap IDs in URLs and bodies — can user A read user B’s data? Test every object reference, not just the obvious ones.
  • BFLA: can a regular user call admin endpoints? Check HTTP method and role-based access on each route.
  • Mass assignment: extra fields in JSON bodies (isAdmin: true) — are they ignored or applied?

3. Input validation & injection

  • SQL injection in query parameters and search endpoints; NoSQL injection in JSON bodies.
  • Command injection via filenames, hostnames, or URL parameters (SSRF territory).
  • XSS in reflected API responses and stored payloads rendered by the front end.
  • XML/XXE if any endpoint accepts XML (legacy systems love this one).

4. Business logic & abuse

  • Rate limiting: on OTP, login, and money-moving endpoints specifically.
  • Race conditions: double-spend scenarios on payments or balance transfers.
  • Cache poisoning: unkeyed headers, CDN caching of authenticated responses.

5. Data exposure

  • Verbose errors leaking stack traces, SQL queries, or internal IPs.
  • Hardcoded secrets in responses, client bundles, or git history.
  • Sensitive fields (passwords, tokens, PII) appearing in logs or analytics payloads.
  • CORS misconfigurations allowing cross-origin reads of authenticated data.

Tools I use

Burp Suite Pro for interception and repeater work, Postman to map the full API surface, and Fiddler when I need to inspect encrypted traffic or mobile calls. For automation, Python scripts turn repetitive checks into one-command scans — which is most of what I mean when I say I “automate security workflows”.
